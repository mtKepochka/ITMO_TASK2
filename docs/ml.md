# ML- и LLM-подход

Система разделяет четыре класса методов с разными требованиями к данным,
задержке и безопасности.

## Rules

Регулярные выражения находят email, телефон и похожий на номер карты
фрагмент. Словари выделяют взлом, мошенничество, утечку, спорное списание,
возврат, блокировку и юридическую угрозу. Denylist запрещает auto-reply для
`payment_issue`, `refund_request` и `account_security`; allowlist содержит
только `service_outage`.

Правила объяснимы и работают при отказе моделей. Их слабость — вариативный
язык и false positives: до production нужны тесты на реальном потоке,
нормализация каналов и специализированный PII-NER как второй детектор.
Снижать recall rules ради большего auto-reply нельзя без оценки safety.

## Classical ML

PoC использует взвешенные фразы. Score преобразуется в эвристический
confidence с поправкой на конкурирующую категорию. Это не обученная и не
откалиброванная вероятность: значение пригодно только для демонстрации
policy и abstention.

Первый production baseline:

1. символьные и словные TF-IDF признаки;
2. Logistic Regression с class weights либо Linear SVM;
3. временной split и подбор гиперпараметров только на validation;
4. калибровка Platt/isotonic на отдельной calibration-части;
5. разные пороги для маршрута, suggest-mode и auto-reply.

Модель обучается внутри компании на исторических тикетах с подтверждённым
финальным маршрутом. Operator override полезен, но не равен автоматически
истинной метке: спорные и изменённые taxonomy-примеры нужно доразмечать
двумя аннотаторами с арбитражем. Open-source модель здесь не нужна до
доказательства, что sparse baseline недостаточен.

Abstention — часть результата, а не ошибка. Неизвестный текст, малый
margin, confidence ниже порога или high-risk сигнал ведут к человеку.
Auto-reply threshold выбирается по ограничению unsafe auto-action rate,
а не по максимальной общей accuracy.

## Retrieval

PoC считает пересечение нормализованных токенов с четырьмя локальными
статьями и добавляет небольшой бонус за категорию. Он возвращает ID,
текст и объяснимый score; слабое совпадение запрещает auto-reply.

Следующий baseline — BM25 с фильтром по актуальной версии, продукту и
языку. Embeddings добавляются после анализа no-hit и synonym errors.
Hybrid retrieval объединяет lexical и dense кандидатов; reranker нужен
только если Recall@k достаточен, но порядок кандидатов остаётся проблемой.
Все варианты должны уметь вернуть `no hit`, а не подставить нерелевантную
статью.

## LLM

LLM допустим только в асинхронной генерации черновика и суммаризации для
оператора. На вход идут редактированный минимум запроса и одна или
несколько разрешённых статей. Prompt запрещает обещать возврат, изменение
аккаунта или факт выполнения операции; ответ проходит schema, PII и
grounding validation.

Инструкции из пользовательского текста считаются недоверенными данными,
что ограничивает prompt injection. Модель не решает PII, риск или
маршрутизацию в одиночку и отсутствует в latency-critical path. Timeout,
invalid output или отсутствие grounded-контекста включают утверждённый
шаблон либо эскалацию. Если детерминированные шаблоны дают сопоставимое
качество и acceptance при меньшем риске/стоимости, LLM для этой категории
следует убрать.

## Policy, реализованный в PoC

Порядок правил: high risk/PII → `escalate`; denylist → `escalate`;
confidence ниже `0.70` → `escalate`; retrieval ниже `0.35` →
`suggest_to_agent`; `service_outage` с сильными сигналами → `auto_reply`;
остальное → `suggest_to_agent`. Числа — демонстрационные параметры, не
результат offline-оценки.
